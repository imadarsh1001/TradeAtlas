# Analyst Methodology

Definitions and limits behind the Analyst-lens tools (`tradeatlas/forecasting.py`, `tradeatlas/analytics.py`) and the golden suites (`evals/`). The authoritative constants live in code — this document paraphrases them; where they ever disagree, code wins and this file gets fixed in the same change.

## Forecast scoring (price-forecasting)

- **Backtest design**: rolling historical cutoffs; at each cutoff only information available then is used. The harness drops the extract's possibly-partial final month before scoring; every scored month is complete. Minimum 24 training months per cutoff.
- **Baselines**: last observed (carries the cutoff price forward); same month last year (the *target* month minus 12 — never the origin minus 12); linear trend (ordinary least squares refit at every cutoff on elapsed calendar positions, so gaps preserve spacing).
- **MAE**: mean absolute error in ₹/quintal, per state × target-period × horizon group. Every method is scored on identical rows within a group.
- **MASE**: MAE ÷ q, where the scaling factor **q** = mean |y_t − y_{t−12}| over the group's scored targets whose t−12 exists in the training panel. q is a scaling constant, not a scored metric, and is printed with every group. By construction the same-month-last-year baseline scores MASE = 1.0 on its own groups. Post-break groups on the pinned extract have 11 seasonal lookback pairs (the lookback reaches into pre-break history — the same lookback the seasonal baseline itself takes; it is information available at the cutoff, not a cross-break aggregation). q undefined → MASE null.
- **Reporting break (ADR 0001)**: targets are grouped "Before November 2025" and "November 2025 onward"; no group's statistics pool observations across the boundary.
- **Provenance**: every report states the manifest's source revision, the scored range, and the training minimum. `evals/golden/analyst.json` numeric expectations are generated by `evals/generate_expectations.py`; a data refresh or computation change regenerates them in the same change.

## Anomaly detection (anomaly-detection)

- **Method**: Iglewicz–Hoaglin modified z-score, 0.6745·(x − median)/MAD, on month-over-month **log changes**; threshold |z| > 3.5.
- **Segmentation**: statistics are computed within each reporting-break segment; the segment's initial month (no within-segment prior month) is unexamined; pairs involving missing values are skipped and counted; a segment with fewer than 6 scored changes yields no flags plus a thin-support caveat; a degenerate MAD (0) flags nothing.
- **Interpretation**: a flag is a signal to investigate, never a proven market event. Examined counts are scored changes, not raw months.

## Coverage (coverage-detection)

- Per requested state: observed months, missing months within the series' own range, longest consecutive gap (0 when none), latest observed month, pre- and post-break counts (separate, never summed), trailing staleness in months.
- **Staleness reference**: the last month of the pinned extract's own range — deterministic, not the wall clock. Whether the snapshot is current *enough* for a live decision is a buyer judgment; the pinned snapshot's observation dates make that judgment possible.

## Known limits

- The pinned extract has no forecast vintages: each completed month is treated as available at its cutoff — an approximation the original data proof documented.
- Only Groundnut for Gujarat and Rajasthan is pinned; other commodities/states abstain explicitly.
- Post-break segments are short (11 scored months); their MAE/MASE rest on thin support — read the target counts before reading the error numbers.
